# Clinical Catalyst & Position Dashboard

Tracks clinical-trial progress and upcoming catalysts for the **meaningful positions**
held by three healthcare/biotech managers — **RTW Investments**, **Avoro Capital
Advisors**, and **Frazier Life Sciences** — and emails a monthly performance +
catalyst brief.

It answers, at a glance:

- **What's about to move?** A *Meaningful Readout Watch* of near-term, high-impact
  binaries (PDUFA dates, Phase 3 readouts), each with a countdown and which
  managers own it.
- **What's on the calendar?** Every dated catalyst bucketed by time-to-event
  (next 30 days → beyond 12 months).
- **Who owns what, and how big?** Top positions per manager with 13F weights, plus
  a *cross-fund conviction* view of names held by more than one manager.
- **How are they performing?** 1M / 3M / YTD / 12M total return per position.
- **What just happened?** Recently reported readouts and recurring commercial
  trajectories to check each earnings season.

> ⚠️ **Not investment advice.** Educational tool. Catalyst dates are estimates
> compiled from company IR and public reporting and can shift — verify against
> primary sources before acting.

---

## What it looks like

- `output/dashboard.html` — the full interactive dashboard (self-contained, works
  offline, light/dark theme aware).
- `output/monthly_email.html` — the monthly email brief (inline-styled, email-safe).

Both are generated from the JSON in `data/` and committed so they render without
running anything.

## Layout

```
clinical-dashboard/
├── data/                     # the tracked universe (edit these to customize)
│   ├── funds.json            # managers + SEC CIKs
│   ├── holdings.json         # top positions per manager (13F weights)
│   ├── catalysts.json        # curated clinical/regulatory catalysts  ← the core
│   ├── companies.json        # ticker ↔ issuer-name ↔ trial-sponsor map
│   ├── prices.json           # generated by refresh_prices.py
│   └── trials.json           # generated by refresh_trials.py
├── scripts/
│   ├── lib.py                # shared helpers (HTTP w/ retry, JSON, dates)
│   ├── refresh_holdings.py   # pull latest 13F-HR from SEC EDGAR
│   ├── refresh_prices.py     # pull EOD prices from Stooq, compute returns
│   ├── refresh_trials.py     # pull trial status from ClinicalTrials.gov v2
│   ├── refresh_all.py        # run all refreshes + rebuild dashboard
│   ├── build_dashboard.py    # data/ → output/dashboard.html
│   ├── build_email.py        # data/ → output/monthly_email.{html,txt}
│   └── send_email.py         # SMTP send of the monthly brief
└── output/                   # generated HTML (committed)
```

Automation lives in `.github/workflows/` at the repo root:
`dashboard-refresh.yml` (weekly) and `monthly-email.yml` (monthly).

## Run it locally

Pure Python standard library — no `pip install` needed.

```bash
cd clinical-dashboard

# Rebuild the dashboard/email from existing data (no network):
python scripts/build_dashboard.py
python scripts/build_email.py

# Refresh live data (needs outbound HTTPS to sec.gov / stooq.com / clinicaltrials.gov):
export DASHBOARD_UA="your-project your.email@example.com"   # SEC requires a contact UA
python scripts/refresh_all.py
```

Open `output/dashboard.html` in a browser.

## Automation (GitHub Actions)

Two scheduled workflows are included and also run on-demand from the **Actions** tab:

| Workflow | Schedule | Does |
|----------|----------|------|
| `dashboard-refresh.yml` | Mondays 12:00 UTC | Refresh holdings/prices/trials, rebuild dashboard, commit |
| `monthly-email.yml` | 1st of month 13:00 UTC | Refresh, build brief, email it, commit |

### Secrets to configure

Repo → **Settings → Secrets and variables → Actions**:

| Secret | Purpose | Example |
|--------|---------|---------|
| `CONTACT_EMAIL` | Contact string in the SEC EDGAR User-Agent | `you@example.com` |
| `SMTP_HOST` | Mail server | `smtp.gmail.com` |
| `SMTP_PORT` | `587` (STARTTLS) or `465` (SSL) | `587` |
| `SMTP_USER` | SMTP username | `you@gmail.com` |
| `SMTP_PASS` | SMTP password / app password | *(Gmail App Password)* |
| `EMAIL_FROM` | From address (defaults to `SMTP_USER`) | `you@gmail.com` |
| `EMAIL_TO` | Recipients, comma-separated | `you@gmail.com,partner@fund.com` |

Works with Gmail (use an [App Password](https://support.google.com/accounts/answer/185833)),
SendGrid, Mailgun, or AWS SES SMTP. Without SMTP secrets, `send_email.py` does a
dry run (prints, doesn't send), so the workflow won't fail before you've set it up.

## Customize what's tracked

Everything is data-driven — no code changes needed to retune the universe:

- **Add / change positions** → edit `data/holdings.json`. Add a matching entry to
  `data/companies.json` (name alias + ClinicalTrials.gov sponsor) so refreshes can
  attach the ticker and pull its trials.
- **Add / change catalysts** → edit `data/catalysts.json`. Fields: `sort_date`
  (ISO, used for ordering), `display` (human label), `precision`, `importance`
  (`high`/`medium`/`low`), `status` (`upcoming`/`reported`/`recurring`), `type`,
  `asset`, `indication`, `description`, `source`.
- **Add a manager** → add to `data/funds.json` with its SEC CIK; the 13F refresh
  and all views pick it up automatically.

The weekly refresh **overwrites** `holdings.json` weights with exact 13F values and
enriches trial status; hand-curated `catalysts.json` is never overwritten (dates
and importance are judgment calls), so that's the file you maintain over time.

## Data sources

| Source | Used for | Auth |
|--------|----------|------|
| SEC EDGAR 13F-HR | Manager holdings & weights | none (descriptive UA required) |
| ClinicalTrials.gov API v2 | Trial phase / status / completion dates | none |
| Stooq | End-of-day prices & returns | none |

All three are free and keyless. Company IR pages are cited per-catalyst in
`catalysts.json` `source` fields.
